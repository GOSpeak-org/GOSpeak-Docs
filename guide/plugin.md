# 插件系统

GOSpeak 插件是以**独立子进程**运行的扩展，用来在不修改主程序的前提下增加能力：内容审核、外部通知、自定义页面等。插件与宿主通过**本机回环 TCP 上的 gRPC** 通信，由宿主分配端口并通过一次性凭据文件传递，插件无需监听对外端口，也无需任何插件凭据配置。

> [!WARNING]
> **拉取即信任：插件没有沙箱、没有签名校验、没有运行期权限边界。** 从插件市场、GitHub 或本地文件安装后，插件即被完全信任，**直接拥有宿主能力**，可以读写用户/房间数据、执行禁言与建房间等写操作。**请只安装你信任的插件和来源**，这等同于在你服务器上运行一段有应用权限的代码。项目不对插件行为承担责任。

## 管理员操作入口

插件由**平台管理员**在「管理 → 插件」页面管理（管理 API 走受保护路由并要求管理员角色）。页面分三块：安装插件、插件列表、运行时版本。

### 安装

在「安装插件」填写来源并安装：

- 插件市场标识；
- GitHub 仓库地址（如 `https://github.com/owner/repo`）；
- 可填写版本 / ref。

安装流程：拉取代码到 `/app/plugins/bin/<plugin_id>/` → 校验 `metadata.yaml` → 执行 `npm ci`（依赖各自隔离）→ 启动插件进程 → 插件经 SDK 完成注册。拉取失败、依赖安装失败或注册失败时该插件被跳过并告警，**不会导致主程序崩溃**。

### 升级

对已安装插件点「升级」：从原来源重新拉取最新版本覆盖插件目录，重新安装依赖并重启。升级会保留插件数据目录（`runtime/state/<plugin_id>/`），失败时保留旧版本并记录告警。

### 重载

点「重载」：不拉新代码，停止当前进程后用本地目录重新启动并重新注册。适用于修改配置或调试插件。

### 启用 / 停用与卸载

- 「停用 / 启用」只切换启用状态并持久化，重启后保持。
- 「卸载」停止进程并删除插件代码目录，但**保留**插件数据目录与审计记录。

## 运行时版本选择

Node.js 运行时由独立的 runtime 插件提供，采用**零自动下载**策略：

- 服务启动时不会下载任何运行时版本；插件根的 Node.js（管理员在页面选装）优先使用，否则自动复用系统 PATH 中的 Node.js。两者都没有时服务仍正常启动，插件被跳过并告警，不会导致主程序 panic。
- 管理员在「管理 → 插件 → 运行时版本 → Node.js」填写版本号（如 `v20.19.0`），可选填写镜像地址，点「安装版本」完成下载与校验；在已安装列表中点「切换」选择当前使用版本。切换后相关插件会重启。
- **Python 仅预留入口**，页面显示但提示暂未开放。

Docker 部署时，插件根目录由 `gospeak-plugins` 卷持久化到 `/app/plugins`，镜像已预置 PATH，不需要也不应该配置插件相关环境变量。详见部署文档的插件节（部署细节以 GOSpeak-Server 仓库的 [`deploy/DEPLOY.md`](https://github.com/GOSpeak-org/GOSpeak-Server/blob/release/deploy/DEPLOY.md) 为准）。

## 插件页面挂载

插件可在注册时声明自己的页面（路由路径、模式 `spa` / `iframe`、入口地址），经管理员确认后挂载到 `/plugins/<plugin_id>/` 前缀：

- `spa` 模式：由宿主按前缀反向代理到插件页面。
- `iframe` 模式：在平台页面内嵌插件页面，带 sandbox 与来源校验。
- 浏览器与插件页面之间的调用经宿主提供的代理端点转发，遵循已确认的路由前缀约束。

用户访问这些页面仍走正常的登录与角色校验。
